# AI Insights: product overview

AI Insights helps STAR users produce a project overview from information already available about a project. It combines project metadata, reported-result context, stored documents, and user-supplied text, then uses a managed prompt to ask a language model for a structured overview.

This document describes backend capabilities in the reviewed branch. It does not establish the behavior of a deployed STAR interface, a measured productivity gain, or an accuracy guarantee.

## Capabilities

| Capability | User purpose | Backend behavior |
| --- | --- | --- |
| Project overview generation | Synthesize available project information | Fetch context, extract supported documents, invoke Bedrock, return results and attempt caching |
| Cached overview retrieval | Reopen the latest saved overview | Return `response.json` and current available-file information without generating again |
| Document deletion | Remove selected stored evidence files | Delete named objects while retaining the saved overview |
| Prompt Manager | Adjust overview-generation instructions | Read defaults/current sections and save a validated full replacement without redeployment |

The repository contains the backend, not a frontend application for these workflows. API consumers own presentation, user review, upload interactions, and decisions about when to regenerate.

## Sources and output

The overview can use three kinds of context: STAR project/results data, supported files in an S3 project prefix, and optional user text. The final path segment of that prefix identifies the STAR contract for metadata retrieval.

Documents are optional. The backend permits up to three supported documents, reduced to two when `text` is non-empty. A request can run from STAR context or user text alone, but still requires a bucket/folder and attempts S3 listing. With no context of any kind, it fails.

PDFs and supported images use Amazon Textract. DOCX, spreadsheets, PowerPoint, and plain text use other readers. The service combines the available content into one prompt and makes a model invocation; it does not use a retrieval/vector-database pipeline in the current implementation.

The response contains the overview, source-processing metadata, received text, a generation timestamp, processing time, and an optional analytics ID. The overview content is generated by the model and requires human review. Unparseable model output can appear as `raw_response` rather than a fully structured overview.

## Prompt editing

The current managed prompt is `project-overview`, divided into role, context, user instructions, and expected output format. Its context variables connect the prompt to actual project information, results, evidence, and user input.

Editors submit all four sections. The backend rejects missing/unknown/duplicated placeholders and blank sections, stores the user version in S3, and keeps code-defined defaults for fallback/reset. Editing changes future generation without a code deployment. It does not revise summaries already saved for projects.

## Cache and file lifecycle

Generation attempts to save the response in the project's S3 folder as `response.json`. Cache persistence is best-effort, so consumers should not equate a successful generation response with proof that later retrieval will return that result.

A cached overview is distinct from the current file list. Adding/deleting evidence or editing the active prompt does not automatically regenerate or invalidate cached data. The consumer must explicitly generate a new overview when it wants those changes reflected.

The deletion endpoint keeps `response.json`. It deletes sequentially and is not an all-or-nothing batch operation.

## Access and dependencies

Generation and prompt replacement have separate CLARISA authorization names. STAR context access uses a separate access token. Some read/deletion endpoints do not have an application authentication dependency; infrastructure controls must be checked in the target environment.

The backend relies on S3, Bedrock Claude Sonnet 4.6, Textract for applicable formats, and optional STAR/analytics/Slack integrations. Required prompt-storage configuration and an analytics URL must be available before startup.
